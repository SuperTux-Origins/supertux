# ECS migration audit

Living document. Every fact below was verified against this checkout
(branch `ecs-refactor`, 2026-10-03), replacing the earlier tarball-based
audit. Numbers are from `grep`/`wc` over `src/` and `data/levels/`.

## Object model

| Class | File | Notes |
|---|---|---|
| `GameObject` | `supertux/game_object.hpp` (186 lines) | Pure-virtual `update()`/`draw()`, plus dead editor hooks (`editor_*`, `has_settings`, `is_saveable`) left over from the removed editor. Has a `GameObjectComponent` slot list queried by `dynamic_cast`. |
| `GameObjectComponent` | `supertux/game_object_component.hpp` | Empty interface. **Only user: `Portable`** (`object/portable.hpp`). Easy to retire. |
| `GameObjectManager` | `supertux/game_object_manager.{hpp,cpp}` | `std::vector<std::unique_ptr<GameObject>>` updated and drawn **in insertion order**; additions/removals deferred to `flush_game_objects()`. Maps by UID, name and `type_index`. |
| `MovingObject` | `supertux/moving_object.hpp` (113 lines) | Owns a `CollisionObject` and implements `CollisionListener`. |
| `CollisionObject` | `collision/collision_object.hpp` (171 lines) | bbox, movement, destination rect, group. Holds a `CollisionListener&` back to its owner. `CollisionSystem` stores raw `CollisionObject*`, so these need **stable addresses**. |
| `CollisionListener` | `collision/collision_listener.hpp` | `collision(GameObject& other, …)` — double dispatch is done by the receiver `dynamic_cast`ing `other`. |
| `Physic` | `supertux/physic.hpp` (89 lines) | Plain value type, no virtuals. Ready to become a component as-is. |
| `BadGuy` | `badguy/badguy.{hpp,cpp}` (286 / 932 lines) | 21 virtual hooks (`active_update`, `collision_player`, `collision_squished`, `collision_bullet`, `ignite`, `freeze`, `kill_fall`, wind, …) and its own state machine. |
| `Player` | `object/player.{hpp,cpp}` (388 / 2,603 lines) | Referenced from 89 other `.cpp` files; `Sector::get_players()` used 53×. |
| `ObjectFactory` / `GameObjectFactory` | `supertux/object_factory.hpp`, `supertux/game_object_factory.cpp` | Name → lambda map; **126 registered names**. |
| `UID` / `TypedUID<T>` | `util/uid.hpp`, `util/typed_uid.hpp` | 32-bit handle (16-bit magic + 16-bit id), resolved via the sector. Has a unit test (`tests/uid_test.cpp`). |
| Scripting | `src/scripting/` (71 files, ~34 exposed classes) | Wrappers generated by miniswig (`mk/cmake/SuperTux/BuildMiniswigWrapper.cmake`); `ExposedObject` stores a `UID`. |

Counts: 59 concrete badguys + `walking_badguy` base in `src/badguy/`
(22 derive from `WalkingBadguy`; `poisonivy` is a factory alias of `ViciousIvy`);
92 headers in `src/object/`. The worldmap (`src/worldmap/`, 12 classes,
`WorldMapSector`) is also a `GameObjectManager` and must keep working.

## Coupling hot spots

The real "spaghetti" is type-switching on collision partners, not the
class count:

- **208 `dynamic_cast<>` in `src/**/*.cpp`**: 65 to `Player`, 19 `MovingObject`,
  17 `BadGuy`, 16 `ItemControlField`, 7 `Portable`, then a long tail
  (`Lantern`, `WalkingBadguy`, `Totem`, `Crusher`, `Bullet`, `Explosion`, …).
- `get_objects_by_type<T>` lookups: mostly singletons (`MusicObject` 17×,
  `AmbientLight` 7×, `Camera`, `TileMap`) — these map naturally to registry
  context variables or singleton views.

## Determinism / test infrastructure already present

- Fixed logical timestep (`LOGICAL_FPS`, `screen_manager.cpp`) and
  `g_game_time`.
- Seeded `gameRandom` (separate from `graphicsRandom`).
- **Demo record/playback**: `--record-demo FILE LEVEL`, `--play-demo FILE
  LEVEL` (`supertux/game_session_recorder.cpp`); the demo file stores the
  RNG seed.
- **Null video driver** (`src/video/null/`, `--renderer null`).
- Unit tests under `tests/` (collision, reader, uid, rect, …).

So the golden-master harness only needs: (1) a per-frame state dump,
(2) exit when the demo ends, (3) a script to run and compare a fixed set
of demos. Nothing has to be built from scratch.

## Savegames

`supertux/savegame.cpp` writes player status and Squirrel state tables
only — no object class names. The migration does not affect save
compatibility.

## Dependencies

- EnTT is not yet in the tree. nixpkgs has `entt` 3.14.0 (header-only).
- `external/` holds vendored libs wired via `add_subdirectory` with
  `EXISTS` fallbacks (`CMakeLists.txt` ~L209–430). EnTT would follow the same
  pattern (system package first, `external/entt` fallback for cross targets).

## Resolved questions

- **Platform scope**: AGENTS.md is authoritative — all five targets
  (Linux, WASM, Android, R36S, MinGW) are live. New code must build on all;
  per-phase cross builds, per-commit Linux builds.
- **Delivery**: direct commits on the working branch (AGENTS.md updated).
